## Hardware quirks found
- **Shoulder ID2 physical stop near 2000-2010** (can't lean back further; stalls at full
  load). The URDF IK happily asks for 1400-1980 — reject those. `pen.py` clamps ID2 >= 2030.
- Wrist flex ID4 EEPROM range 1718..3782. ID4 ~3000 = jaws roughly horizontal outward,
  ~3760 = jaws down; lower = jaws swing outward/up.
- Wrist roll ID5 is mechanically blocked near 2383 going down from 3192 (marker/cable hits arm).
- Model direction cheats (at the working pose): ID3 -100 -> up ~2.4 cm & out ~2 cm;
  ID2 +100 -> down ~2.5 cm.
- Occasional garbled register reads (temp 247, V 3.8). A single bad temp read tripped the
  old overheat check and released every motor. `teleop.py` now needs 3 consecutive
  plausible (55..100 C) readings.
- Killing teleop with SIGTERM leaves torque on (holding); it can take ~5 s to exit.
  Only `{"release": true}` or a real overheat turns torque off.
- **Any command sent to teleop executes.** Don't "probe limits" with a real joint command
  (a roll probe to 100 was accepted and started rotating).
- Cameras: after USB re-plug both enumerated fine (Gemini "RGB Camera" + "USB Camera").
  The Gemini gets bumped/re-aimed by people often; re-crop each time.

## Tools added
- `pen.py`: relative Cartesian pen moves on top of teleop. Uses the URDF only for *relative*
  motion, keeps jaw pitch (axis z) fixed, captures per-joint sag (target - measured) once,
  streams joint waypoints every 3 mm. `ARM_CTL` = the dir holding teleop's cmds/status
  (default `./ctl`, gitignored). `Pen(reset=True)` re-captures pose/offsets.
- `pen_probe.py`: descend 5 mm steps printing commanded vs measured z (contact finder).
- `teleop_cmd.sh` now uses `ARM_CTL` instead of a hard-coded scratch path.
